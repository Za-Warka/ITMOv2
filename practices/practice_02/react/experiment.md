# ReAct

- Цель: спроектировать и прогнать экспериментальные нагрузки для проверки SEC-1, API-1, REL-1 и контрактов OUT-1 на эндпоинте POST /api/reviews, собрать метрики и принять решение Go/No-Go.
- Доступные входы: context.md, problem.md, tests_load.md (из practice_02/react), prompts.md (P1-03), датасеты diff по матрице S1/M1/M2/L1/T1.
- Разрешённые действия: моделирование профилей k6, использование LLM-ста ба с задержками и таймаутами, сбор телеметрии по OBS-1, анализ метрик, оформление evidence.
- Запрещённые действия: логирование содержимого diff или ответов, действия approve/merge/edit, изменение внешних лимитов без согласования, интернет-доступ.
- Максимальное число шагов: 8.
- Условие остановки и вопроса человеку: превышение 5xx > 2% 2 минуты, отсутствие 413 для >20k, обнаружение утечки секретов, «висящие» запросы > 11 с; спросить архитектора об утверждении порогов pXX и целевого RPS.

## Запрос

Провести эксперимент: сравнить поведение сервиса под профилями Baseline, Limit (API-1), REL-1 (near-timeout/timeout), Stress/Spike/Soak согласно tests_load.md, подтвердить: 1) 413 для >20k без вызова LLM; 2) SEC-1 — секреты не попадают в LLM-стаб; 3) REL-1 — таймаут 10 с приводит к контролируемому ответу; 4) OUT-1 — структура ответа соблюдается.
