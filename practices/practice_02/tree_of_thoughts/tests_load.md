# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Высокая частота POST /api/reviews с diff ≤20k; дополнительно проверяем near-timeout (REL-1) и >20k (HTTP 413) в рамках одного сценария. | 50 RPS, 5 минут; near-timeout: задержка внешнего LLM ≈10 с; >20k: отправка diff > 20 000 символов. | 5xx = 0; p50 (медиана) < 200 мс; >20k → HTTP 413 (слишком большой размер тела, без вызова LLM) в 100% случаев; REL-1: при 10 с — контролируемый ответ. | Латентность p50/p95, доля 5xx, соблюдение REL-1 (контролируемый ответ при 10 с), соблюдение API-1 (413 при >20k) и отсутствие вызова LLM (по телеметрии), соблюдение OBS-1 (не логировать содержимое). | Инструмент: k6; стенд: локальный с телеметрией (request_id, длительность, статус); профили данных: ≤20k и >20k; проверки: >20k → HTTP 413 без LLM; near-timeout → контролируемый ответ. |

Если нагрузочное тестирование пока не требуется, оно запускается после стабилизации API и готовности стенда с телеметрией: включены SEC-1, API-1 и REL-1; метрики собираются.
