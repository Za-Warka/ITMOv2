# Разработка Repo Atlas

## Запуск

Из `practices/practice_04`:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:3000. Node.js 22+; проект проверен на Node.js 26.10.0. Демо работает без внешних запросов: синтетические данные, локальные шрифты, SVG-графика. Первый запуск требует установки npm-пакетов.

Для реального проекта вставить `owner/repo` или HTTPS-ссылку GitHub. Без токена действуют публичные лимиты GitHub. Необязательный `GITHUB_TOKEN` задаётся в `.env.local` по образцу `.env.example`, затем сервер перезапускается. Токен не передаётся браузеру; приватные репозитории отклоняются независимо от прав токена.

`npm run build` собирает production-версию, `npm start` запускает её. Нужен Node.js runtime, не статический хостинг.

## Проверки после сохранения

```sh
npm run check
npm run check:watch
```

Первая команда запускает ESLint, TypeScript и 65 unit-тестов. Вторая устанавливает файловый save hook: следит за `src`, `tests`, `mcp`, после изменения `.ts`, `.tsx`, `.css` ждёт 500 ms и вызывает тот же runner. Повторные изменения объединяются; результаты выводятся в терминал и доступны агенту через вывод процесса. Это файловый watcher, не выдуманная настройка hooks Codex. Его нужно держать запущенным во время работы; Ctrl+C останавливает наблюдение. `scripts/check` — переносимая shell-обёртка, запускается через `sh scripts/check`.

В среде с ограниченным доступом к системному watcher или локальным портам может потребоваться разрешение на запуск вне sandbox.

## Собственный MCP

```sh
npm run mcp
npm run mcp:verify
```

MCP работает через stdio. Команда `mcp` ожидает подключение MCP-клиента и не является HTTP-сайтом. `preview_civilization` принимает `snapshot`, ISO-дату `date` и необязательный `includeBots`. Возвращает результат общей функции `buildWorld`: эпоху, авторов, участки, здания и охват данных. GitHub-токен не нужен.

`mcp:verify` запускает отдельный сервер, делает `tools/list` и три настоящих `tools/call` через SDK Client: корректный снимок, неверная дата, отрицательный размер языка. Проверяет результаты и записывает `docs/mcp-verification.json`.

`mcp/config.example.json` — шаблон настройки клиентов, поддерживающих `mcpServers` и `cwd`. Заменить абсолютный путь своим. Синтаксис настройки конкретного клиента нужно сверить с его документацией; файл не регистрирует сервер автоматически в Codex. Если клиент не поддерживает `cwd`, использовать абсолютные пути к `node_modules/tsx/dist/loader.mjs` после `--import` и к `mcp/server.ts`.

## Модель и ограничения

- `src/domain/world.ts` — чистая модель; сайт и MCP используют одну функцию.
- `src/server/github/client.ts` — только сервер: проверка приватности, фиксация head SHA, до десяти страниц по 100 коммитов, нормализация и ограниченный кэш.
- `src/app/api/repository/route.ts` передаёт NDJSON: реальные этапы загрузки и финальный снимок либо ошибку.
- Текущий языковой состав фиксирован во времени. Исторический анализ языков, релизы, ветки и экспорт пока не реализованы.
- Авторы определяются по GitHub ID. Для непривязанных авторов используется HMAC email, сам email клиенту не возвращается. Без `AUTHOR_HASH_SECRET` ключ живёт до перезапуска сервера; задайте постоянный серверный секрет для стабильных анонимных ID между запусками.
- Карта использует алгоритм v2, постоянный seed repository ID и стабильные участки. Эпоха отражает количество наблюдаемых коммитов, не качество проекта.
- При обрыве загрузки после первой страницы доступная часть истории сохраняется с предупреждением. Неполная история никогда не выдаётся за полную.
- Отмена в браузере прекращает чтение результата. Уже начатая общая серверная загрузка может завершиться в кэш для других клиентов; каждый запрос GitHub ограничен timeout 12 секунд.
- Кэш процесса непостоянный: 15 минут, до 50 репозиториев, максимум пять одновременных загрузок. Для публичного массового сервиса нужны отдельные квоты на клиентов и постоянное хранилище.

## Культуры и деятели

Поддерживается 21 язык, включая основные языки GitHub и популярные языки мобильной, научной и веб-разработки. Каталог не является рейтингом популярности. Ориентир для основного набора: [GitHub Octoverse](https://github.blog/news-insights/octoverse/octoverse-2024/#the-most-popular-programming-languages); расширение включает Rust, Swift, Kotlin, Dart, R, Scala, Lua, Ruby, SQL, HTML и CSS.

`src/domain/cultures.ts` содержит названия культур, архитектурные стили и по десять титулов. `src/components/building-model.tsx` рисует отдельные силуэты. Все здания используют язык с наибольшим числом байт текущего снимка; дополнительные языки остаются видны в статистике. При равных долях выбор детерминирован по имени языка.

Во вкладке «Деятели» отображаются до десяти авторов-людей по числу уникальных коммитов до выбранной даты. Доля рассчитывается среди всех человеческих коммитов в этой выборке, не только топ-10. При равенстве применяется ID автора. Титулы — игровые роли, не реальные должности. Частичная история явно отмечается. В демо есть селектор для сравнения 21 культуры без GitHub.

## Использованные скиллы

`frontend-design` задаёт процесс: сначала выбрать предметную визуальную идею, затем токены и компоновку, после реализации оценить скриншот. Для атласа центральным элементом стал остров с собственной SVG-архитектурой, а не набор карточек. Во время проверки увеличен мелкий текст и скорректировано распределение культур, чтобы языки действительно различались на карте. Результат проверяется в браузере, наличие SKILL.md само по себе не является подтверждением применения.

`playwright` использован через локальный wrapper `skills/playwright/scripts/playwright_cli.sh`. Снимки структуры страницы дают актуальные элементы для взаимодействия; screenshot позволяет проверить компоновку. Результаты лежат в `output/playwright` и не включаются в Git как автоматически генерируемые файлы.

Шрифты Literata и Golos Text поставляются локально npm-пакетами Fontsource, лицензии находятся в соответствующих пакетах. SVG-иллюстрации написаны для этого проекта.
