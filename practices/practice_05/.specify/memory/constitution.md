# Repo Atlas Constitution

## Core Principles

### I. Проверяемое происхождение
Все события MUST выводиться из наблюдаемых уникальных коммитов. Неполный охват и синтетическое демо MUST обозначаться явно. История не является оценкой людей.

### II. Детерминированная модель
Логика MUST оставаться чистой, отдельно от React. Одинаковые входы дают одинаковые события и карту; перемотка обратима. UTC и SHA определяют порядок.

### III. Законченные сценарии
Каждая фича MUST включать модель, доступный русский интерфейс и проверку ошибок. Новые зависимости добавляются только при необходимости.

### IV. Проверки до завершения
Для каждой фичи MUST пройти npm run check и браузерный сценарий. Новая доменная логика MUST иметь тесты границ и регрессий; результаты фиксируются без выдуманных успехов.

### V. Рабочая область и приватность
Изменения MUST оставаться в practice_05. Токены и email MUST отсутствовать в ссылках и клиентских данных. Существующие серверные контракты сохраняются, если фича не требует их изменения.

## Constraints
Next.js, React, strict TypeScript, CSS Modules, SVG, Vitest. Палитра paper #F5F0E4, surface #FFFCF4, sand #D9C9AA, meadow #A8BB8A, forest #315642, ink #29382D. Literata и Golos Text. Управление клавиатурой, видимый фокус, ширины 360/768/1440.

## Development Workflow
Для каждой фичи отдельно: speckit-specify → speckit-plan → speckit-checklist и авторское ревью требований → speckit-tasks → speckit-analyze → speckit-implement → проверки → speckit-converge. Анализ не заменяет тесты; ревью выполняет агент, не выдавая его за одобрение пользователя.

## Governance
Изменения принципов сопровождаются обоснованием и SemVer. Каждая спецификация и план проверяются на соответствие. Прямые указания пользователя имеют приоритет. Источник правил — AGENTS.md.
