# Repo Atlas: что показать ревьюверу

Этот файл следует разделу «Что студент показывает ревьюверу» из [README.md](README.md). Здесь собраны примеры из разработки, файлы реализации и короткие подтверждения. Браузерные проверки выполнены 6 октября 2026 года; MCP и новый hook повторно проверены 7 октября 2026 года по московскому времени. Команды ниже запускаются из `practices/practice_04`.

## 1. Как применялись правила, skill, MCP и автоматическая проверка

| Инструмент | Реальное применение | Что предъявить |
|---|---|---|
| `AGENTS.md` | До реализации агент прочитал правила. Зафиксированы бежево-зелёная палитра, SVG-карта, разделение модели и интерфейса, ограничения GitHub. После уточнений добавлены культуры и деятели. | [Правила](AGENTS.md), [цветовые токены](src/styles/global.css), [общая модель](src/domain/world.ts), [GitHub-адаптер](src/server/github/client.ts) |

После просмотра скриншотов увеличил мелкий текст и исправил планшетную компоновку. | [Skill](skills/frontend-design/SKILL.md), [SVG-модели](src/components/building-model.tsx), [скриншот европейской культуры](docs/evidence/culture-classical.png) |

Конкретный пример применения правила: текущие доли языков GitHub не выдаются за исторические. Основная культура фиксируется по текущему снимку, а перемотка меняет коммиты, жителей и топ авторов. Это отражено и в интерфейсе, и в модели. Другой пример — ограничение в 1000 коммитов: при усечении истории сервер возвращает `historyComplete: false`, а интерфейс сообщает о неполном охвате.

## 2. Зачем выбраны эти инструменты

- **Правила проекта** удерживают продуктовую идею и технические ограничения между запросами: сайт должен оставаться атласом истории репозитория, а не произвольным dashboard.
- **Frontend-design** помогает перевести пожелания о цветах и исторической стилистике в конкретные модели, типографику и компоновку.
- **Playwright** проверяет поведение уже работающего интерфейса. Успешная компиляция не обнаружила бы проблему гидратации SVG или неудобное расположение элементов на планшете.
- **Собственный MCP** даёт агенту способ проверить расчёт цивилизации без браузера. Модель не дублируется: сайт и MCP вызывают `buildWorld`.
- **Hook** запускает проверки после правки без отдельного напоминания. Агент получает диагностику и может исправить ошибку в том же рабочем цикле.

Для самого сайта используется GitHub REST API через серверный код. Это не MCP: GitHub загружает историю, а наш MCP рассчитывает мир по уже подготовленному снимку. Приватные репозитории не поддерживаются; MCP-проверки не требуют сети или GitHub-токена.

## 3. Как устроены и как применялись готовые skills

### Разбор frontend-design — 4 предложения

[Frontend-design](skills/frontend-design/SKILL.md) — готовый skill от Anthropic с инструкциями по проектированию интерфейса, а не генератор сайта одной командой. Он предлагает сначала определить предметную визуальную идею, выбрать цвета, типографику и компоновку, затем реализовать интерфейс и оценить результат. В Repo Atlas этим центральным образом стал остров с изометрическими зданиями в спокойной бежево-зелёной палитре. После визуальной проверки были увеличены мелкие подписи и изменена планшетная компоновка, поэтому применение skill подтверждается результатом и доработками, а не только его наличием в папке.

### Разбор playwright — 4 предложения

[Playwright](skills/playwright/SKILL.md) — готовый skill из каталога OpenAI для управления настоящим браузером из терминала. Кроме инструкции он содержит shell-wrapper и справочные файлы с командами: открыть страницу, получить snapshot, выполнить действие и сохранить screenshot. В нашем проекте через него проверены перемотка истории, выбор здания, включение ботов, ввод неверной ссылки, загрузка `octocat/Hello-World` и переключение культур. Проверка обнаружила ошибку гидратации SVG `<title>`, которую исправили, после чего повторный прогон прошёл без ошибок JavaScript.

### Повторение браузерного примера

В первом терминале:

```sh
npm run dev
```

Во втором:

```sh
bash skills/playwright/scripts/playwright_cli.sh --session review open http://127.0.0.1:3000
bash skills/playwright/scripts/playwright_cli.sh --session review snapshot
```

В snapshot видны актуальные ссылки на элементы. Для конкретного элемента можно выполнить `click <ref>` или `select <ref> 'C#'`; `<ref>` берётся из свежего snapshot, а не копируется из старого запуска. Для воспроизводимой проверки по доступным названиям:

```sh
bash skills/playwright/scripts/playwright_cli.sh --session review run-code 'async (page) => {
  await page.getByRole("combobox", { name: "Культура примера" }).selectOption("C#");
  await page.getByRole("tab", { name: "Деятели", exact: true }).click();
  const court = page.getByRole("list", { name: "Топ контрибьюторов" });
  if (await court.locator("li").count() !== 10) throw new Error("Ожидалось 10 деятелей");
  await page.getByRole("button", { name: "К началу истории", exact: true }).click();
  if (await court.locator("li").count() !== 1) throw new Error("В начале истории должен остаться один автор");
  return { courtAtStart: 1, rewind: true };
}'
```

Эта команда — инструкция для повторения. Подтверждение уже выполненного полного прогона: все 21 культуры переключились без `pageerror`, в конце demo было 10 деятелей, в начале — один; на 360 px отсутствовало горизонтальное переполнение. Источник результатов: [docs/verification.md](docs/verification.md). Сохранённые в `docs/evidence` скриншоты относятся к проверке 6 октября; позднее заголовок блока деятелей был сокращён до «Совет цивилизации».

## 4. Наш MCP: устройство и реальные вызовы

**Сервер:** `repo-atlas`, transport — **stdio**, реализация на TypeScript с `@modelcontextprotocol/sdk`. **Инструмент:** `preview_civilization`, только чтение, без изменения файлов или загрузки репозитория.

Вход:

- `snapshot`: нормализованный репозиторий, коммиты, авторы, объёмы языков и охват истории;
- `date`: ISO-дата, на которую строится мир;
- `includeBots`: необязательный флаг для населения. В топ деятелей боты всё равно не включаются.

Выход: JSON в текстовом блоке MCP с эпохой, числом коммитов, авторами, участками, зданиями, культурой, топом деятелей и информацией о полноте данных. Zod проверяет структуру входа, даты и неотрицательные объёмы языков. Вся предметная логика вызывается из [buildWorld](src/domain/world.ts).

### Запуск проверки

```sh
npm run mcp:verify
```

Команда запускает отдельный stdio-сервер, соединяется с ним через SDK Client, выполняет `tools/list` и три `tools/call`. Это реальные MCP-вызовы; тест не подменяет их прямым вызовом функции. В текущую конфигурацию Codex сервер автоматически не зарегистрирован. Для подключения есть [шаблон MCP-конфигурации](mcp/config.example.json): требуется указать свой абсолютный `cwd` и проверить, поддерживает ли клиент такой формат.

### Корректный вход

В [проверочном клиенте](scripts/verify-mcp.ts) берутся первые 30 коммитов demo, дата — `2023-03-06T18:24:00.000Z`, история помечается как частичная. Вызов:

```ts
await client.callTool({
  name: "preview_civilization",
  arguments: { snapshot, date: snapshot.coverage.rangeEnd },
});
```

Сокращённый фактический результат:

```json
{
  "algorithmVersion": 2,
  "dominantLanguage": "TypeScript",
  "eraName": "Поселение",
  "commitCount": 30,
  "lots": 4
}
```

В полном результате также один автор и пять построек: четыре жилых участка и центральное здание. Это совпадает с правилами: от 25 коммитов начинается «Поселение», один автор даёт `ceil(4 * sqrt(1)) = 4` участка.

### Ошибочный вход

На том же снимке заменяется только дата:

```ts
await client.callTool({
  name: "preview_civilization",
  arguments: { snapshot, date: "not-a-date" },
});
```

Фактический ответ:

```json
{
  "content": [{
    "type": "text",
    "text": "MCP error -32602: Input validation error: Invalid arguments for tool preview_civilization: Invalid ISO datetime at date"
  }],
  "isError": true
}
```

Второй ошибочный сценарий — `snapshot.languages = { Python: -1 }`: результат также `isError: true`, ошибка указывает на `snapshot.languages.Python` и требование `>=0`.

Полные входы успешного сценария и ответы всех проверок: [docs/mcp-verification.json](docs/mcp-verification.json). Для ошибок в журнале сохранены изменённые поля; остальные совпадают с успешным входом. Консоль реального повторного запуска:

```text
MCP passed: tools/list, 30 commits → Поселение, invalid date and negative language rejected. Evidence: docs/mcp-verification.json
```

## 5. Hook после сохранения и пример его применения

Это **файловый after-save hook**, работающий независимо от AI-клиента. Он не называется встроенным hook Codex и не требует несуществующих ключей его конфигурации.

Цепочка:

```text
Сохранение .ts / .tsx / .css в src, tests или mcp
  → watcher, объединение событий за 500 ms
  → hooks/after-save.mjs
  → sh scripts/check
  → ESLint → TypeScript → Vitest
  → PASS / FAIL и код завершения в терминал агента
  → output/hooks/latest.log
```

Файлы:

- [hooks/config.json](hooks/config.json) — наблюдаемые папки, расширения, задержка, runner и путь журнала.
- [hooks/after-save.mjs](hooks/after-save.mjs) — запуск проверок, передача stdout/stderr и запись результата.
- [scripts/watch-check.mjs](scripts/watch-check.mjs) — наблюдение, debounce, последовательная очередь запусков.
- [scripts/check](scripts/check) — единый runner `npm run check`.
- [scripts/demo-hook.mjs](scripts/demo-hook.mjs) — воспроизводимая демонстрация настоящего события сохранения.

### Обычная работа

```sh
npm run check:watch
```

Оставить процесс работающим и сохранить правку в `src/domain/cultures.ts`. Hook сам выполнит проверки. Если проверки уже идут, новые изменения будут обработаны следующим запуском; параллельных запусков внутри одного watcher нет. Запись журнала не запускает проверки повторно, потому что `output` не наблюдается. В конце работы остановить watcher через Ctrl+C.

### Демонстрация без изменения пользовательского кода

```sh
npm run hook:demo
```

Демонстрация запускает watcher с `--once`, дожидается `READY`, сохраняет новый временный `src/hook-demo-<pid>.ts`, ждёт автоматической проверки и удаляет только этот временный файл. Код сайта не меняется. После успешного запуска копия журнала сохраняется в `docs/hook-example.log`; команда завершается ошибкой, если hook не сработал или проверки не прошли.

Короткое подтверждение реального запуска 7 октября:

```text
[save-hook] Changed: src/hook-demo-51185.ts
[save-hook] Runner: sh scripts/check
Test Files  3 passed (3)
Tests       65 passed (65)
[save-hook] Result: PASS (exit 0)
```

[Полный журнал](docs/hook-example.log) содержит команды lint/typecheck/test, дату и результат. Агент получил тот же вывод из запущенного процесса — результат не остался только в файле. В журнале timestamp указан в UTC: `2026-10-06T21:05:36.298Z` соответствует 7 октября, 00:05 по Москве.

В sandbox macOS наблюдение завершалось `EMFILE`; после разрешённого запуска вне sandbox демонстрация прошла. Если среда запрещает системный watcher, это нужно устранить или разрешить его запуск; ручной `npm run check` не следует выдавать за автоматический hook.

## 6. Где потребовались решения студента

По истории работы, студент:

1. Выбрал саму идею: показывать историю репозитория как рост цивилизации, связывая язык с культурой, коммиты — с развитием, авторов — с размером города.
2. Задал спокойную светлую бежево-зелёную палитру и попросил заранее оформить замысел в `AGENTS.md`.
3. Уточнил первую версию: потребовал разные модели для C#, C++ и Java, отдельную вкладку деятелей и культурные титулы.
4. Расширил задачу до распространённых языков — вместо трёх культур получился каталог из 21 набора.
5. Отдельно уточнил назначение MCP и затем попросил подготовить подтверждения для защиты, а не ограничиваться наличием файлов.

Личный вывод уже записан студентом в [reflection.md](reflection.md): серьёзных проблем с его точки зрения не было, чему помогла предварительно подготовленная среда с правилами и skills. Это его оценка; технические ошибки, найденные и исправленные агентом, отдельно отражены в журнале проверок. Из разработки также видно, что конкретные продуктовые уточнения меняют результат: запрос «разные культуры» превратился в различимые модели только после уточнения архитектуры и ролей.

## 7. Короткий порядок показа на защите

1. Открыть `AGENTS.md` и показать два правила вместе с реализацией: палитру и честное отображение неполной истории.
2. Открыть сайт, переключить C# → C++ → Java, показать «Деятелей» и перемотать историю к началу.
3. Показать SKILL.md, wrapper Playwright и один сохранённый скриншот; объяснить, что проверялось после реализации.
4. Выполнить `npm run mcp:verify`; показать успешный результат и `isError` в JSON-журнале.
5. Выполнить `npm run hook:demo`; показать, что runner стартовал после сохранения файла, а вывод вернулся в терминал.
6. Завершить собственными наблюдениями из `reflection.md`.

Приложенные журналы подтверждают конкретные локальные прогоны. Они не означают автоматическую регистрацию MCP в Codex, отдельный worktree для каждой фичи или другие действия, которые здесь не выполнялись.
