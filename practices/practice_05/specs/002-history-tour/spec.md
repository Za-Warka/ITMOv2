# Feature Specification: Экскурсия по истории
**Feature Branch**: practice_05
**Created**: 2026-10-28
**Status**: Reviewed
**Input**: Реализовать фичу 2 — до пяти проверяемых остановок истории.

## User Scenarios & Testing
### User Story 1 — Пройти историю города (Priority: P1)
Посетитель запускает экскурсию и понимает, какие события развивали город.
**Why this priority**: превращает перемотку в понятный рассказ.
**Independent Test**: пройти все остановки демо и вернуться назад.
**Acceptance Scenarios**:
1. Given история, When нажато «Начать экскурсию», Then воспроизведение остановлено, открыта летопись и первая остановка; видны номер, дата, объяснение и происхождение.
2. Given активная экскурсия, When «Далее» или «Назад», Then карта вычислена на точную дату остановки; переход назад воспроизводит прежние числа.
3. Given реальный проект, When открыта остановка, Then доступна ссылка на исходный коммит; для демо — текст о синтетическом событии.

### User Story 2 — Управлять без конфликтов (Priority: P2)
**Why this priority**: ручное исследование должно оставаться свободным.
**Independent Test**: завершить экскурсию и использовать обычный таймлайн.
**Acceptance Scenarios**:
1. Given экскурсия, When завершение, ручная перемотка, play, смена культуры или начало загрузки другого репозитория, Then экскурсия закрыта и не перехватывает управление; при завершении дата остаётся выбранной.
2. Given пустая история, When открыта карта, Then экскурсия недоступна с объяснением; для одного коммита — одна остановка и отключённые края навигации.

### Edge Cases
Одинаковые SHA считаются один раз. При равных датах порядок определяет SHA, карта включает все коммиты до даты, а не обещает отдельные ancestry-шаги. Боты не становятся событиями новых жителей. Частичная история называется наблюдаемой, без заявления о первом коммите проекта. Первая остановка может быть bot-коммитом. Дублирование одного коммита в остановках запрещено.

## Requirements
### Functional Requirements
- **FR-001**: Система MUST выбирать от 1 до 5 остановок для непустой истории: первый наблюдаемый коммит, затем до четырёх переходов эпох после основания; свободные места заполняются первыми появлениями людей в хронологическом порядке. Один SHA — одна остановка, при совпадении приоритет у начала, затем эпохи, затем жителя. Итог отсортирован по UTC и SHA.
- **FR-002**: Каждая остановка MUST содержать точную дату, заголовок, объяснение на основе метрики, SHA происхождения. Переход эпохи описывает накопленное число наблюдаемых коммитов; при совпадающих датах это порог события, а карта включает весь момент.
- **FR-003**: Запуск и навигация MUST останавливать play, выбирать летопись, очищать выделение здания и устанавливать точную дату; кнопки краёв недоступны.
- **FR-004**: Реальные события MUST давать GitHub-ссылку; демо MUST обозначаться синтетическим; частичный охват MUST иметь пояснение в экскурсии.
- **FR-005**: Ручные действия из US2 MUST завершать экскурсию; завершение сохраняет дату, ничего не запускается автоматически.
- **FR-006**: Пустое состояние MUST иметь объяснение; кнопки MUST работать с клавиатуры; остановки доступны текстом, без анимации и горизонтальной прокрутки на 360/768/1440.

### Key Entities
Остановка: тип начала/эпохи/жителя, дата, SHA, объяснение. Экскурсия: список остановок и активный индекс либо неактивное состояние.

## Success Criteria
### Measurable Outcomes
- **SC-001**: На демо от 1 до 5 уникальных остановок, навигация воспроизводима в обе стороны.
- **SC-002**: Каждое утверждение об эпохе или жителе связано с наблюдаемым коммитом; ботов среди событий жителей нет.
- **SC-003**: После каждого перечисленного ручного действия экскурсия закрыта; обычный таймлайн и ссылка на эпоху продолжают работать.

## Assumptions
Релизы и LLM не нужны. Основание представлено первой остановкой, без отдельного дублирующего события. Настройка включения ботов не меняет выбор остановок. Переходы мгновенные, камера остаётся под контролем пользователя. До пяти остановок — фиксированная верхняя граница, не обещание найти ровно пять событий.
